\section{Experiments}

\subsection{Experimental Setup}

\paragraph{Research questions.}
We evaluate three questions. \emph{RQ1} asks whether explicit graph
structure improves the completeness of multi-hop evidence retrieval
under a fixed top-$k$ budget. \emph{RQ2} asks whether relation-aware
graph encoding further improves evidence-path recovery beyond
heuristic graph reranking and task-adapted dense retrieval.
\emph{RQ3} asks whether execution-level provenance improves complete
dependency recovery in simulated agent trajectories, both without
task-specific training and with a learned relation-aware encoder, and
whether the gain is primarily attributable to graph message passing,
relation types, edge weights, or hard negatives.

\paragraph{Datasets and splits.}
The evidence-path experiments use HotpotQA, 2WikiMultiHopQA, and
MuSiQue. For each dataset, we retain its training set, use the first
500 labeled development examples for model selection, and reserve the
remaining development examples for final testing. We additionally
construct a controlled execution-provenance benchmark from
2WikiMultiHopQA. It maps two recoverable supporting facts to typed
tool calls, tool outputs, and data-flow dependencies, and introduces
structurally similar non-gold branches. This benchmark isolates the
value of execution dependencies, but it is not intended to substitute
for naturally occurring multi-agent traces. Table~\ref{tab:data} gives
the split sizes.

\paragraph{Compared methods.}
For evidence-path retrieval, \textbf{BM25} and \textbf{Dense} are
lexical and pretrained dense baselines. \textbf{BM25-Graph} and
\textbf{Dense-Graph} rerank their initial results with fixed
evidence-graph heuristics. \textbf{Dense R-GCN} uses frozen dense
representations as node features in a relational graph convolutional
network. \textbf{Dense-FT} fine-tunes the dense retriever on the task,
whereas \textbf{Dense-FT R-GCN} initializes the R-GCN with the
fine-tuned representations and is our full model for this setting.

For simulated trajectories, \textbf{BM25}, \textbf{Dense}, and
\textbf{Dense-FT} provide sparse, pretrained dense, and task-adapted
dense baselines. \textbf{FastGraphRAG-style} is a compact, non-LLM
entity-graph baseline: it deterministically extracts and links
entities, combines lexical and dense seeds with Personalized PageRank,
and projects entity scores back to evidence. It follows the non-LLM
entity-search idea of FastGraphRAG and is not a reproduction of a full
GraphRAG pipeline with LLM-based community summarization or generation.
\textbf{EPGM} performs bounded search over a typed
execution-provenance graph and combines semantic relevance, dependency
completeness, field binding, and grounding into a path score, without
task-specific parameter training. \textbf{EPGM R-GCN} is its learned
relation-aware counterpart. It applies three layers of relation-specific
message passing to pretrained dense node features, ranks
\texttt{ToolOutput} candidates, and jointly predicts logical
output-to-output dependency edges. Dense-FT is trained for one epoch,
whereas EPGM R-GCN is trained for 15 epochs and selected by development
Full Support@5; both use random seed 13.

\paragraph{Metrics.}
Recall@$k$ measures the fraction of gold evidence retrieved in the
top $k$, while Full Support@$k$ is one only when all gold evidence is
present. MRR measures the rank of the first gold item. Connected
Evidence Recall measures whether retrieved evidence remains connected
in the induced graph. Path Recall@10 measures whether the retrieved
subgraph contains a valid path connecting the gold evidence, and Edge
Recall@10 measures direct recovery of gold dependency edges. HotpotQA
does not provide directed gold dependency paths, so we report
connectivity rather than path and edge recall for that dataset. A dash
in the path columns indicates that a method does not return a provenance
subgraph, so the metric is not defined rather than zero.
To further distinguish ``retrieving part of the evidence on average''
from ``recovering the complete support chain,'' we also use the
completeness gap
$\Delta_{\mathrm{comp}}@k=\mathrm{Recall}@k-\mathrm{Full\ Support}@k$
as a diagnostic quantity. A smaller gap means that ordinary recall is
less inflated by examples in which only part of the gold evidence is
retrieved. This quantity is used to interpret the primary metrics rather
than as an additional headline metric.

\subsection{Execution-Provenance Model Ablation}

\paragraph{Implementation and ablation design.}
The execution-provenance R-GCN does not append a hand-crafted graph bonus
to the final ranking score. Instead, it learns relational propagation over
the entire trajectory. Each request uses its unique \texttt{Task} node as
the query anchor. Text from \texttt{Task}, \texttt{Agent},
\texttt{ToolCall}, \texttt{ToolOutput}, and other node types is prefixed
with the corresponding E5 query or passage marker and encoded as a
normalized, frozen 768-dimensional text representation. The model
concatenates a 16-dimensional node-type embedding and projects the result
into a 256-dimensional hidden space. Every native edge is expanded into
forward and reverse message edges. Relations such as \texttt{contains},
\texttt{invokes}, \texttt{returns}, and \texttt{feeds} use separate
transformation matrices, and \texttt{feeds} is further specialized by the
binding between an output field and an input parameter. The full model
stacks three R-GCN layers. A message can be written as
$w_{uv}c_{v,r}^{-1}W_rh_u$, where $W_r$ is relation-specific, $w_{uv}$ is
the graph-construction edge weight, and $c_{v,r}$ normalizes the in-degree
for relation $r$. The aggregated message is added to a self-state
transformation and followed by ReLU, dropout (0.1), and layer
normalization. Task semantics, call hierarchy, and field-level data flow
are therefore encoded in the same node state.

The model uses two prediction heads over the shared graph representation.
The candidate head takes $[h_o,h_q,h_o\odot h_q]$ and produces a retrieval
logit for every \texttt{ToolOutput}. The dependency head takes
$[h_s,h_t,h_s\odot h_t,h_q]$ and scores candidate logical transitions.
These transitions are not arbitrary node pairs: a \texttt{feeds} edge
from an upstream \texttt{ToolOutput} to a downstream \texttt{ToolCall},
followed by that call's \texttt{returns} edge to another
\texttt{ToolOutput}, is collapsed into one output-to-output dependency.
Edge supervision therefore indicates whether a downstream call consumes
an upstream output. Training combines candidate binary cross-entropy with
positive-reweighted dependency-edge binary cross-entropy:
$\mathcal{L}=\mathcal{L}_{\mathrm{cand}}+
0.5\mathcal{L}_{\mathrm{edge}}$. The full run uses AdamW, a learning rate
of $10^{-4}$, batch size 128, gradient clipping at 1.0, and up to 15
epochs. Each positive is paired with two random negatives, two BM25 hard
negatives, and two dense hard negatives. At inference, the candidate head
ranks all \texttt{ToolOutput} nodes. A logical transition can be emitted
only if both endpoints enter the top-$k$ set; among transitions with the
same source, the decoder keeps only the highest-scoring successor and
restores its native \texttt{feeds}/\texttt{returns} trace. Path@10 and
Edge@10 therefore jointly test candidate coverage and dependency decoding
rather than evaluating the edge classifier independently of retrieval.

Following this computation path, we run four targeted variants on the
same 74,012/500/2,851 train, selection, and test splits. \emph{w/o graph}
sets the number of graph-convolution layers to zero while retaining the
node-type representation, candidate scorer, and dependency-edge head,
isolating the propagation block. \emph{w/o edge type} retains graph
connectivity and edge weights but replaces relation-specific transforms
with one shared transform. \emph{w/o edge weight} retains adjacency and
relation labels but sets every edge weight to one. \emph{w/o hard
negatives} removes BM25 and dense hard negatives while retaining random
easy negatives. Every variant uses random seed 13 and selects its own
checkpoint by Full Support@5 on the same 500-example development set.
These results come from an independent training batch, so
Table~\ref{tab:provenance-ablation} supports within-table comparisons
only. The small difference between its full model and the main model in
Table~\ref{tab:provenance} should not be interpreted as a method change.

Removing graph message passing causes the largest degradation and affects
every metric. Recall@2, Full Support@5, and MRR fall by 36.48, 28.94, and
21.64 points, while Path Recall@10 and Edge Recall@10 fall by 16.98 and
18.17 points. In sample counts, \emph{w/o graph} completely recovers 825
fewer trajectories at top-5 and leaves 335 more trajectories incomplete at
top-10. Because this variant retains the same frozen text representations,
node-type embeddings, candidate MLP, and dependency-edge MLP, the gap
locates the main gain in the relational propagation block rather than in
the text encoder or output heads. Three-layer propagation lets an upstream
evidence output influence downstream outputs through
\texttt{feeds}/\texttt{returns} connections and carries query-anchor
information through the call hierarchy, helping both gold outputs move
into the small retrieval budget together.

Replacing relation-specific transforms with a shared transform lowers
Recall@2 and Full Support@5 by 7.42 and 3.86 points and lowers path and edge
recall by 1.44 and 1.54 points. It also yields 110 fewer complete top-5
trajectories and increases the number of incomplete top-10 trajectories
from 24 to 58. This variant retains the same adjacency, propagation depth,
and edge weights; the changed mechanism is whether $W_r$ distinguishes
relations. It therefore isolates typed propagation more precisely than
removing the entire graph. Call-hierarchy edges and field-level data-flow
edges carry directions and semantics that one untyped transformation does
not fully replace. Relation types are especially useful in early ranking,
where they separate messages from structurally adjacent but functionally
different \texttt{Agent}, \texttt{ToolCall}, and \texttt{ToolOutput}
nodes.

The evidence for edge weights is more nuanced. Uniform weighting raises
Full Support@5 and Full Support@10 by 0.18 and 0.11 points, corresponding
to only five and three additional complete examples among 2,851 test
queries. At the same time, MRR, Path Recall@10, and Edge Recall@10 fall by
3.65, 1.51, and 2.00 points. The current results therefore partially
support the claim that edge weights help rank the first relevant output
and recover dependencies, while their effect on top-$k$ complete support
is approximately neutral on this split. This pattern matches the
implementation: weights directly scale propagated messages and can alter
fine-grained candidate order and edge logits, but Full Support does not
change if both gold outputs remain inside the same top-$k$ set. Removing
hard negatives raises flat ranking metrics by at most 0.14 points but
lowers path and edge recall by 0.32 and 0.46 points. Hard negatives are
therefore better characterized as an auxiliary training strategy in the
current setting: they may slightly help structural recovery, but the
single-seed results show only a small and directionally mixed independent
contribution.

Development and test results provide evidence in the same direction. The
best Dev FS@5 of \emph{w/o graph} is 28.80 points below the full model, and
that of \emph{w/o edge type} is 4.80 points lower. On the test set, these
variants leave 359 and 58 top-10 trajectories incomplete, respectively,
compared with only 24 for the full model. The full model reaches its best
checkpoint at epoch 12, whereas every ablation reaches its best value at
epoch 15, so the gaps are not caused by selecting earlier checkpoints for
the ablated models. The full model's Dev FS@5 is 97.40\%, 28.80 and 4.80
points above \emph{w/o graph} and \emph{w/o edge type}, and this ordering
persists on the independent test set. Uniform edge weighting and
hard-negative removal also trail the full model on Dev FS@5 by 0.40 and
0.60 points, while their small test-set reversals in Full Support do not
appear on development. This mismatch further suggests that differences of
only a few tenths of a point may reflect split or seed variation rather
than a stable advantage. However, all four ablations attain their best
checkpoints at the 15-epoch training limit, so longer training could still
change some absolute values. The experiment compares components under a
common training budget but does not establish that every variant has fully
converged by epoch 15.

\paragraph{Residual errors point to second-hop coverage rather than
indiscriminate subgraph expansion.}
All 24 residual failures of the full model are stored. In 22 cases, the
model recovers one of the two gold outputs and misses only the other; only
two cases miss both. The remaining errors are therefore mostly
``near-complete but missing one hop.'' Future improvements should
prioritize seed coverage and joint ranking for the second dependency
output rather than merely expanding the returned subgraph. Because a
dependency edge is decoded only after both endpoints enter the top-10
set, these 22 single-endpoint misses also explain why small candidate-
recall changes propagate to Path@10 and Edge@10.

Output density rules out the alternative explanation that predicting more
edges is sufficient to raise edge recall. \emph{w/o edge weight} and
\emph{w/o hard negatives} return 9.15 and 9.03 edges on average, both more
than the full model's 8.91, yet achieve lower Edge Recall@10. The full
model therefore obtains higher edge recall with fewer average edges,
indicating that relation transforms and edge weights improve dependency
selection quality rather than making the decoder connect more candidates
indiscriminately. The current decoder keeps at most one successor per
source, which matches the two-hop chain structure of the synthetic
benchmark. Natural trajectories in which one output is consumed by
multiple calls will additionally require evaluation of branching decoders
and edge precision.

Taken together, the main table, component metrics, development selection,
and failure decomposition reveal a clear contribution hierarchy. Graph
message passing is the primary source of early-ranking, complete-support,
and dependency-recovery gains. Relation-specific transforms provide a
second stable gain. Edge weights offer substantial but metric-dependent
help for MRR, path recovery, and edge recovery. Hard negatives contribute
less in the current configuration and are better viewed as an auxiliary
training strategy. This hierarchy follows the model's actual computation
path and avoids attributing the near-ceiling aggregate result merely to
``using a graph.''

\subsection{Limitations and Robustness}

The current experiments already provide partial evidence for structured
execution-provenance memory from three perspectives: controlled retrieval,
complete evidence recovery, and dependency reconstruction. Their scope is
still concentrated on retrieval, so they provide only partial support for
the full multi-agent memory lifecycle. First, the synthetic provenance
benchmark is deterministically derived from labeled question-answering
evidence chains rather than collected from heterogeneous, naturally
occurring agent logs. Its conversion also uses supporting-fact information
to keep gold transitions recoverable when semantic graph construction
misses them. The near-ceiling EPGM R-GCN results directly show that the
model can recover relevant outputs and dependencies on a controlled,
label-derived execution topology, but they provide only limited indirect
evidence for generalization to independently constructed agent traces.
Reproducing the same advantage on natural logs containing tool failures,
retries, parallel branches, evidence revisions, and cross-agent handoffs
would substantially broaden the scope of this conclusion.

Second, all results use one fixed split and one training seed; multi-seed
variance and bootstrap confidence intervals are not yet reported. The
reversals of a few tenths of a point after removing edge weights or hard
negatives indicate that these small effects require repeated experiments
to determine their direction. In contrast, removing graph propagation
causes cross-metric losses of 16.98--36.48 points that also appear in the
development set, test set, and failure counts, making this the more robust
current conclusion. Third, the experiments evaluate retrieval, complete
support, and path recovery. They therefore partially support the claim
that structured memory can provide more complete evidence to downstream
reasoning. System-level effects such as reducing unsupported claims or
improving downstream impact tracing receive only indirect support until
the retrieved subgraphs are integrated into real decision or generation
tasks. Path and edge evaluation also remains recall-centered; adding edge
precision, F1, and branch-level completeness would more fully quantify
overprediction and multi-branch recovery.

Fourth, \emph{w/o graph} removes only message passing while retaining
node-type embeddings, the candidate scorer, logical transitions enumerated
from graph structure, and the dependency-edge head. It therefore answers
whether propagation is necessary rather than capturing every difference
between a graph model and a fully flat model. The independently trained
Dense-FT method in the main experiment provides the flat text baseline.
Further component attribution should separately remove node types,
field-binding features, and the edge-prediction loss, shuffle data-flow
relations, and evaluate invalidation penalties on trajectories containing
actual evidence revisions. Overall, the current results constitute direct
evidence for effective execution-provenance retrieval, relational message
passing, and dependency recovery, and provide partial experimental support
for a complete multi-agent memory system. Broader system-level conclusions
can be strengthened through multi-seed repetition, natural trajectories,
and end-to-end tasks.
