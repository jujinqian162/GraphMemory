\begin{abstract}
Flat agent memory can retrieve individually relevant records while missing the complete dependency chain required by an evidence-heavy task. We propose Execution-Provenance Graph Memory (EPGM), which organizes tasks, agents, tool calls, tool outputs, and related artifacts in a typed graph with native execution edges such as \texttt{contains}, \texttt{invokes}, \texttt{returns}, and field-bound \texttt{feeds}. EPGM provides deterministic structured retrieval and a learned EPGM R-GCN that jointly ranks candidate outputs and predicts logical dependencies over frozen E5-base-v2 features. We evaluate the structured-retrieval hypothesis at three complementary levels: large-scale multi-hop evidence graphs, a controlled label-derived execution-provenance benchmark, and qualitative cases from one real multi-agent trace. On HotpotQA, 2WikiMultiHopQA, and MuSiQue-Ans, the reported seed-13 runs show that adding relation-aware propagation to a task-adapted dense retriever improves Full Support@5 by 4.33--13.01 percentage points. In the current seed-13 snapshot of the controlled provenance benchmark, EPGM R-GCN improves Full Support@5 over Dense-FT by 13.72 points and reaches 87.66\% Edge F1@10; removing graph propagation lowers these metrics by 12.00 and 23.32 points, respectively. The final report will replace these interim comparisons with three-seed means, standard deviations, and paired 95\% confidence intervals. Real-trace cases further show how typed traversal can co-locate support and revision evidence that flat and entity-graph retrieval separate. These results support EPGM's main benefit: completing compact evidence sets and exposing their dependencies, rather than merely improving the first relevant hit.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Large language model (LLM) agents increasingly rely on memory, tool
use, and multi-agent collaboration to solve complex, long-horizon
tasks~\cite{park2023generative,packer2023memgpt,yao2023react,
wu2023autogen,li2023camel}. In practical applications such as cloud
troubleshooting, enterprise question answering, and operational
decision support, agents coordinate over retrieved documents, tool
outputs, logs, intermediate claims, and evolving task states. These
settings are evidence-heavy: a final answer is reliable only when the
system can recover the supporting evidence and the execution steps that
produced it.

Existing agent-memory systems typically preserve interaction histories,
reflections, observations, or task experiences and retrieve relevant
records when needed~\cite{park2023generative,packer2023memgpt,
shinn2023reflexion}. Tool-using and multi-agent frameworks similarly
record actions, observations, messages, and tool results as execution
traces~\cite{yao2023react,wu2023autogen}. In most cases, however, these
records are stored as chronological histories, summaries, or
independently embedded memory items. Such representations are effective
for semantic recall, but they provide limited support for reasoning
about how one memory item depends on another.

This creates a central failure mode for evidence-heavy retrieval.
Retrieved memories are often \emph{evidence-fragmented}: they may be
semantically related to a query, yet fail to place the complete support
set inside a fixed top-$k$ budget, or fail to expose the dependency path
that connects an upstream tool output to a downstream one. Graph-based
retrieval and memory methods partially mitigate fragmentation by
organizing documents, entities, or notes into relational
structures~\cite{edge2024graphrag,gutierrez2024hipporag,
guo2024lightrag,xu2025amem,rezazadeh2025collaborative}. Their relations,
however, are primarily semantic, entity-level, or access-oriented and
generally do not natively encode execution-level data flow: which agent
invoked a tool, which call returned an output, which output field fed a
later call, or which candidate outputs form a required dependency chain.
Multi-agent systems can fail precisely through such coordination and
localization errors~\cite{cemri2025why}.

Consider a multi-hop question that requires two ordered supporting
facts, each realized as a tool output. A dense retriever may rank the
first-hop output highly because it overlaps the query surface form, yet
miss the second-hop output that only becomes relevant after the first
hop is known. An entity-graph method may connect related mentions, but
still not recover the directed execution dependency between the two
outputs. The system therefore needs not only relevant memories, but an
explicit execution-provenance structure over tool calls and outputs, and
a retriever that can complete the support set under a small budget.

This observation motivates a different view of multi-agent memory.
Rather than treating memory as an unordered collection of retrievable
records, we organize it around the execution dependencies connecting
tasks, agents, tool calls, tool outputs, and optional higher-level
artifacts such as claims or decisions. The representation should
preserve how information is produced and consumed during execution, so
that retrieval can return compact evidence sets and dependency paths
instead of isolated snippets.

Realizing this idea introduces three technical challenges. First, the
system must construct reliable provenance relations from heterogeneous
execution events, at least including tool calls, tool outputs, and
output-to-call data flow. Second, it must retrieve a compact evidence
subgraph rather than an unrestricted neighborhood of loosely related
traces, distinguishing evidential support and execution dependence from
pure semantic similarity. Third, when a learned encoder is used, it must
propagate information over typed edges so that upstream evidence can
raise the rank of downstream dependents, rather than only rescoring
isolated nodes.

To address these challenges, we propose
\emph{Execution-Provenance Graph Memory} (EPGM), a structured memory
layer for evidence-heavy agent systems, as illustrated in
Figure~\ref{fig:epgm-overview}. EPGM converts execution events into a
typed directed graph whose core nodes are tasks, agents, tool calls, and
tool outputs, and whose native edges include \texttt{contains},
\texttt{invokes}, \texttt{returns}, and field-bound \texttt{feeds}. The
same schema also admits optional nodes such as observations, evidence
items, claims, verifications, decisions, and answers for richer traces.
Based on this representation, EPGM supports a deterministic structured
retriever with dependency-path and typed-beam presets, together with a
learned relation-aware encoder (EPGM R-GCN) that applies multi-layer R-GCN
message passing over frozen dense node features, ranks
\texttt{ToolOutput} candidates from a unique \texttt{Task} query anchor,
and jointly predicts logical output-to-output dependencies.

Evaluating execution-provenance memory presents a tension between
scale, control, and realism. Standard multi-hop QA benchmarks provide
large-scale supervision but do not contain native agent executions.
Synthetic provenance trajectories expose controlled output dependencies
and support trainable component ablations, but remain label-derived
simulations. Real multi-agent traces closely match the target setting,
yet are expensive to collect and too limited for training a relational
model. We therefore evaluate EPGM at three complementary levels rather
than treating any single setting as interchangeable
(Section~\ref{sec:experiments}). \emph{RQ1} asks whether relation-aware
graph retrieval improves complete evidence-set recovery on large-scale
multi-hop benchmarks. \emph{RQ2} asks whether EPGM can recover complete
output dependencies in controlled execution-provenance trajectories and
which structural components drive the gain. \emph{RQ3} asks, via qualitative cases on a real multi-agent trace,
whether the same schema exposes support and revision structure that flat
retrieval buries. Across these settings,
relation-aware structure most helps when relevance is distributed across
dependent artifacts: large-scale benchmarks provide complete-support
point estimates, the controlled benchmark isolates dependency learning and
graph message passing, and the real-trace study provides qualitative
evidence for support and revision-aware paths. End-to-end unsupported-claim
reduction and revision-impact accuracy remain future work.

Our contributions are summarized as follows:
\begin{itemize}
    \item We introduce EPGM, a typed execution-provenance memory that
    represents tasks, agents, tool calls, tool outputs, and their
    production and data-flow dependencies, with one deterministic
    structured retriever offering two frozen presets and a learned EPGM
    R-GCN that jointly ranks outputs and predicts logical dependencies.

    \item We develop a controlled synthetic execution-provenance
    benchmark that isolates required dependencies among matched
    distractor branches and supports component-level ablations of graph
    propagation, relation types, edge weights, and hard negatives.

    \item We evaluate the structured-retrieval hypothesis through
    large-scale evidence benchmarks, controlled synthetic trajectories,
    and qualitative real-trace cases, providing complementary evidence
    across scale, controllability, and scenario realism.
\end{itemize}


\section{Related Work}

\subsection{Memory and Retrieval for Language Agents}

Memory has become a central component of language-agent systems, enabling agents to retain past observations, interactions, reflections, and task experiences beyond the immediate context window. Generative Agents introduced a memory stream that stores observations and supports reflection and planning over past experiences~\cite{park2023generative}. Reflexion further showed that verbal feedback can serve as episodic memory to improve subsequent agent trials~\cite{shinn2023reflexion}. MemGPT frames memory management as a system-level problem, separating short-term context from longer-term archival and recall memory~\cite{packer2023memgpt}. These works demonstrate that memory is important for persistent and adaptive agent behavior.

Retrieval-augmented generation and dense retrieval methods provide another foundation for agent memory, where relevant external information is retrieved and injected into the model context~\cite{lewis2020rag,karpukhin2020dpr}. More recent agent-memory systems move beyond flat retrieval by organizing memories into structured or evolving forms. A-MEM dynamically constructs interconnected memory notes to support long-term agent memory evolution~\cite{xu2025amem}, while Collaborative Memory studies memory sharing across users and agents with dynamic access control~\cite{rezazadeh2025collaborative}. These methods improve long-term recall, memory organization, and memory sharing. However, they primarily focus on what memories should be stored, linked, shared, or retrieved. In contrast, our work focuses on how memories function as evidence within a multi-agent execution process: how they are produced, verified, reused, contradicted, and propagated across agents. Rather than retrieving isolated memory items, our method retrieves evidence paths that connect observations, tool outputs, intermediate claims, and final answers.

\subsection{Tool Use, Multi-Agent Systems, and Evidence Grounding}

Tool use enables language models to interact with external environments, APIs, documents, and computational resources. MRKL systems combine language models with external symbolic modules and knowledge sources~\cite{karpas2022mrkl}. Toolformer studies how language models can learn to call tools through self-supervised signals~\cite{schick2023toolformer}. ReAct interleaves reasoning and acting, producing trajectories that contain thoughts, actions, and observations~\cite{yao2023react}. Such trajectories naturally contain valuable execution evidence, including tool calls, tool outputs, intermediate observations, and reasoning steps.

Multi-agent systems extend this paradigm by allowing multiple language agents to communicate, specialize, and coordinate over complex tasks. CAMEL explores role-playing communicative agents for cooperative problem solving~\cite{li2023camel}, and AutoGen provides a framework for building LLM applications through multi-agent conversation~\cite{wu2023autogen}. While multi-agent collaboration increases flexibility, it also introduces new failure modes. Recent analysis shows that multi-agent LLM systems may fail due to specification errors, inter-agent misalignment, verification failures, and coordination issues~\cite{cemri2025why}. These failures are particularly important in evidence-heavy tasks, where final answers depend on multiple sources, tool outputs, and intermediate claims.

Existing tool-use and multi-agent systems often record execution traces, but these traces are usually treated as logs, conversational histories, or unstructured contexts. As a result, it remains difficult to answer questions such as which agent produced a claim, which evidence supports it, whether the evidence was verified, and which downstream decisions depend on it. Our work addresses this gap by converting multi-agent execution traces into a typed provenance graph. This allows agents to retrieve structured evidence paths and to expose the execution dependencies that later support revision analysis.

\subsection{Graph-Based Dependency Modeling}

Graphs provide a natural way to represent entities, relations, dependencies, and information flow. In retrieval-augmented generation, graph-based methods have been used to organize knowledge and improve reasoning over complex corpora. GraphRAG constructs graph structures over text collections to support query-focused summarization~\cite{edge2024graphrag}. HippoRAG combines knowledge graphs with long-term memory retrieval inspired by human memory mechanisms~\cite{gutierrez2024hipporag}. LightRAG further explores graph-enhanced retrieval to capture relationships that may be missed by flat vector representations~\cite{guo2024lightrag}. These works show that graph structures can improve retrieval by exposing relationships among documents, entities, and concepts.

Graph-based memory methods also demonstrate the value of relational organization for agents. A-MEM links memory notes into an evolving memory network~\cite{xu2025amem}, and Collaborative Memory represents memory sharing and access relations across users and agents~\cite{rezazadeh2025collaborative}. However, existing graph-based retrieval and memory methods usually model semantic, entity-level, or access-control relationships. They do not explicitly model execution-level evidence dependencies among agents, tool outputs, intermediate claims, verification results, and final answers.

Our work is also related to provenance modeling and distributed tracing. The W3C PROV model defines provenance as information about entities, activities, and agents involved in producing a result~\cite{w3c2013provdm,lebo2013provo,missier2013prov}. Distributed tracing systems such as OpenTelemetry record execution paths across software components~\cite{opentelemetry2026traces}. Inspired by these ideas, we model multi-agent memory as an execution-provenance graph. Unlike traditional provenance systems that primarily support retrospective data or system auditing, our graph memory is designed to be actively used by language agents for evidence-path retrieval and dependency recovery, with revision impact analysis as a natural extension of the same structure.


\section{Problem Formulation}

We study evidence-path and execution-dependency retrieval for
evidence-heavy agent systems. A task $q$ is solved by one or more
language agents that interact with tools, documents, or other agents and
produce an execution trace
\[
\tau_q = \{s_1, s_2, \ldots, s_T\},
\]
where each step $s_t$ may record a tool call, a tool output, a retrieved
document, an observation, an intermediate claim, or a final answer.
Standard memory mechanisms store $\tau_q$ as a chronological history or
embed each step independently. Both choices discard the structural
dependencies among calls, outputs, and later uses of those outputs.

We cast the core problem as compact support recovery over a typed graph
memory $\mathcal{M}$. Given a query $q$ and budget $k$, the system
returns a ranked candidate set and, when dependencies are defined, a
dependency subgraph
\[
S_q \subseteq \mathcal{M}.
\]
For multi-hop evidence-path settings, gold targets are supporting
sentences or facts and optional directed bridges among them. For
controlled execution-provenance settings, gold targets are
\texttt{ToolOutput} nodes together with required output-to-output
dependencies induced by \texttt{feeds}/\texttt{returns} chains. For
the real multi-agent trace study, gold targets are manually annotated
memory nodes and typed audit or support edges over a fuller schema.

Let $G_q$ denote the gold support set and, when available, the gold
directed dependency set $E_q$. The primary objectives used throughout
the experiments are complete support recovery and dependency recovery
under the top-$k$ budget:
\begin{equation}
\begin{aligned}
\mathrm{FullSupport}@k
&=
\mathbf{1}\!\left[G_q \subseteq \mathrm{TopK}(S_q)\right],\\
\mathrm{PathRecall}@k
&=
\mathbf{1}\!\left[
G_q \subseteq \mathrm{TopK}(S_q)
\;\wedge\;
\forall(u,v)\in E_q,\;v\text{ is reachable from }u
\text{ in }S_q[\mathrm{TopK}]
\right].
\end{aligned}
\end{equation}
Ordinary Recall@$k$ and MRR remain useful diagnostics, but they can be
inflated by partial hits that recover only one member of a multi-output
dependency. We therefore also monitor the completeness gap
$\Delta_{\mathrm{comp}}@k=\mathrm{Recall}@k-\mathrm{FullSupport}@k$.
When a method emits predicted dependencies, Edge Recall, Edge Precision,
and Edge F1 evaluate the quality of those edges rather than candidate
ranking alone.

The graph schema can also support downstream impact analysis: if an
evidence or output node $e$ is revised or invalidated, reachable
dependent nodes can be collected by traversing outgoing provenance
edges. We view this as a structural consequence of execution
provenance, but the experiments in this paper measure retrieval,
complete support, and dependency recovery rather than end-to-end
revision impact accuracy.


\section{Execution-Provenance Graph Memory}

To address the above problem, we propose \emph{Execution-Provenance
Graph Memory} (EPGM), a structured memory layer that represents agent
execution traces as a typed directed graph. The key idea is to treat
memory not as a flat set of past records, but as a graph of execution
dependencies. This allows retrieval to return not only relevant memory
items, but also the evidence sets and dependency paths that explain how
outputs were produced and consumed.


\subsection{Graph Memory Representation}
\label{sec:graph-memory-representation}

We represent shared memory as a typed directed graph
\begin{equation}
\mathcal{G}=(\mathcal{V},\mathcal{E},\phi,\psi),
\end{equation}
where $\mathcal{V}$ and $\mathcal{E}$ denote the node and edge sets, and
$\phi:\mathcal{V}\rightarrow\mathcal{T}_v$ and
$\psi:\mathcal{E}\rightarrow\mathcal{T}_e$ assign node and edge types.

The schema contains ten node types:
\texttt{Task}, \texttt{Agent}, \texttt{ToolCall}, \texttt{ToolOutput},
\texttt{Answer}, \texttt{Observation}, \texttt{Evidence},
\texttt{Claim}, \texttt{Verification}, and \texttt{Decision}. Each node
stores textual content and metadata needed for encoding and auditing.
In the evaluated execution-provenance benchmark, the active core is the
\texttt{Task}/\texttt{Agent}/\texttt{ToolCall}/\texttt{ToolOutput}
backbone: every request has exactly one \texttt{Task} query anchor, and
ranking candidates are \texttt{ToolOutput} nodes. The remaining node
types are supported so that richer multi-agent traces can be ingested
without changing the memory interface.

The native edge inventory used by construction and by the learned
encoder comprises execution and optional semantic relations:
\texttt{contains}, \texttt{invokes}, \texttt{returns}, \texttt{feeds},
\texttt{grounds}, \texttt{precedes}, \texttt{supports},
\texttt{verifies}, \texttt{depends\_on}, \texttt{contradicts},
\texttt{invalidates}, \texttt{affects}, and \texttt{supersedes}.
The relations that matter most for the current experiments are:
\begin{itemize}
    \item \texttt{contains}: a task owns an agent, call, or output;
    \item \texttt{invokes}: an agent issues a tool call;
    \item \texttt{returns}: a tool call produces a tool output;
    \item \texttt{feeds}: an upstream tool output supplies a field that
    is consumed by a downstream tool call, with an explicit field
    binding.
\end{itemize}
A logical output-to-output dependency is not stored as an arbitrary node
pair. It is induced only by a chain
\[
\texttt{ToolOutput}_s
\xrightarrow{\texttt{feeds}}
\texttt{ToolCall}
\xrightarrow{\texttt{returns}}
\texttt{ToolOutput}_t,
\]
which the public decoder may emit as one directed logical
\texttt{sequential} edge while restoring the native three-node trace.

    \centering

    \caption{Core synthetic execution-provenance chain (tool calls/outputs); real traces also use claim/revision edges.
    A task contains an agent that invokes tool calls; each call returns
    a tool output; and a field-bound \texttt{feeds} edge links an
    upstream output to a downstream call, inducing the logical

    \label{fig:epgm-example}

Figure~\ref{fig:epgm-example} illustrates the evaluated core chain. In
the synthetic 2Wiki provenance setting, each recoverable ordered pair of
supporting facts is mapped to typed tool calls and tool outputs, with
exactly two ordinary \texttt{feeds} successors per source output under
the current converter protocol: one rank-1 semantic head and one
rank-bucketed branch. The required dependency is inserted as an ordinary
head or branch, and a matched non-gold branch is required when the gold
edge is not the head. Source-local confidences are softmax-normalized
and mapped to edge weights so that the two \texttt{feeds} weights sum to
1.5. This yields a label-conditioned topology with matched distractors
rather than a substitute for naturally occurring multi-agent logs.

For conventional multi-hop evidence-path experiments, we use the
dataset-specific evidence graph over candidate sentences or facts, with
sequential, query-overlap, entity-overlap, and bridge relations; HotpotQA
provides connectivity structure rather than directed gold dependency
paths. EPGM therefore has one shared retrieval goal---complete support
under a budget---and complementary graph realizations detailed next.


\subsection{Evaluation Instantiations}
\label{sec:eval-instantiations}

The shared EPGM interface admits more than one graph realization. We
distinguish them explicitly so that large-scale proxy results are not
mistaken for native multi-agent measurements.

\paragraph{Evidence-graph instantiation (RQ1).}
Multi-hop QA experiments operate over candidate sentences or facts with
sequential, query-overlap, entity-overlap, and bridge edges. Candidates are
evidence items; the target is
the complete supporting set (and path connectivity when gold edges
exist). Dense R-GCN and Dense-FT R-GCN instantiate relation-aware
propagation on this reduced-form graph. The setting does \emph{not}
represent native agent execution; it tests the more general hypothesis
that relational propagation improves complete support recovery under a
fixed top-$k$ budget.

\paragraph{Execution-provenance instantiation (RQ2 and RQ3).}
Synthetic trajectories and the real multi-agent study use the typed
execution schema. The controlled benchmark concentrates on the
\texttt{Task}/\texttt{Agent}/\texttt{ToolCall}/\texttt{ToolOutput}
backbone with \texttt{contains}, \texttt{invokes}, \texttt{returns}, and
field-bound \texttt{feeds}; ranking candidates are \texttt{ToolOutput}
nodes, and supervision targets both the support set and logical
output-to-output dependencies. The real-trace study uses the same
interface with a fuller node inventory---including observations, claims,
verifications, decisions, and answers---and audit edges such as
\texttt{supports}, \texttt{contradicts}, and \texttt{invalidates}. No
real-trace example is used to train or select EPGM R-GCN; RQ3 is a
qualitative case study of training-free structured retrieval on a real
session, not a scored ranking benchmark.

\subsection{Graph Construction from Execution Events}

EPGM is a typed graph over execution artifacts rather than a flat log.
Conceptually, each event $s_t$ in a trace $\tau_q$ contributes a local
update of the form
\[
\mathcal{G}_t = \textsc{UpdateGraph}(\mathcal{G}_{t-1}, s_t),
\]
so the same schema can be maintained as events arrive. Our experiments
do \emph{not} evaluate streaming online maintenance, latency under
incremental writes, or partial-graph retrieval mid-trajectory. For every
task we materialize a complete static graph offline from the full
synthetic trajectory or the recorded multi-agent session, then run
retrieval on $\mathcal{G}_T$. Evidence-graph experiments for RQ1 likewise
build one static candidate graph per example using sequential,
query-overlap, entity-overlap, and bridge rules. The materialization process performs three operations.

First, it creates typed nodes from the recorded artifacts. A tool call
becomes a \texttt{ToolCall} node linked to its \texttt{Agent} and
\texttt{Task}; a tool output becomes a \texttt{ToolOutput} linked to the
producing call; optional claim or decision records are admitted by the
same interface when present in a trace.

Second, it adds deterministic execution edges. A task
\texttt{contains} its agents, calls, and outputs; an agent
\texttt{invokes} a call; a call \texttt{returns} an output. When an
upstream output field is bound to a downstream call parameter, the graph
adds a \texttt{feeds} edge with that binding. In the synthetic converter,
successor selection is performed offline by a pinned hybrid BM25/dense
scorer over non-self candidates, after which the required dependency and
a matched distractor branch are materialized as ordinary \texttt{feeds}
edges. No gold-only feature enters the hybrid score used to propose
successors; however, the gold dependency is inserted after proposal and is
therefore present in the inference graph by construction. This benchmark
evaluates ranking and recovery over a label-conditioned graph, not
dependency discovery from unlabeled execution logs.

Third, it retains optional semantic or audit edges such as
\texttt{supports}, \texttt{contradicts}, or \texttt{invalidates} when a
richer trace provides them. These edges enlarge the schema for revision
analysis, but the controlled benchmark and the reported retrievers
concentrate on call hierarchy and \texttt{feeds} data flow. All reported
retrieval metrics are computed on these offline-materialized static
graphs.


\subsection{Evidence Tracing over Graph Memory}
\label{sec:evidence-tracing}

Given a query, EPGM retrieves a compact support set and, when
dependencies are defined, a dependency subgraph. A deterministic retriever
and a learned encoder share the same graph interface.

\paragraph{Training-free structured retrieval.}
One deterministic implementation exposes two frozen presets for different
graph regimes; neither preset learns parameters.

\emph{Dependency-path EPGM} (synthetic tool-output setting) starts from
the top $S{=}5$ dense seeds and expands only along directed dependency
edges in
$\{\texttt{returns},\texttt{feeds},\texttt{grounds},\texttt{supports},
\texttt{depends\_on}\}$.
A candidate path is accepted only if it contains exactly one
\texttt{feeds} edge and one \texttt{returns} edge, the \texttt{feeds}
binding matches recorded field/parameter endpoints, and no path node is
invalidated or superseded. Path confidence is the geometric mean of
\texttt{feeds} weights times $\mathrm{e}^{-\eta(|E_p|-2)}$ with
$\eta{=}0.04$; paths below confidence $0.2$ are rejected. Accepted
partners are stably inserted after their anchors while protecting the
dense top $N{=}2$, preserving the dense score multiset. This scorer tests
whether explicit \texttt{feeds}/\texttt{returns} structure can complete
output dependencies beyond flat dense ranking.

\emph{Typed-beam EPGM} (real multi-agent traces) handles mixed semantic
nodes and audit edges. Dense retrieval provides the base ranking; the top
$S{=}8$ nodes are seeds. From each seed a bidirectional beam search
(width $32$, depth $\le 4$, $\le 4000$ expansions) never traverses
\texttt{contains} and never expands \emph{through} task/agent hubs (they
may be endpoints only). Each step multiplies a fixed type prior
$\pi(\psi(e))$ (e.g., $0.9$ for \texttt{supports}, $0.85$ for
\texttt{contradicts}/\texttt{invalidates}, $0.6$ for \texttt{feeds}), a
reverse-direction factor $0.85$ when walking against the stored
orientation, and hop decay $\delta^{h}$ with $\delta{=}0.6$. The best path
score reaching candidate $v$ is
\begin{equation}
s_{\mathrm{path}}(v)
=
r(s^{\star})
\prod_{h=0}^{H-1}
\big(\pi(\psi(e_h))\,\rho_h\,\delta^{h}\big),
\end{equation}
where $r(s^{\star})$ is min--max-normalized dense relevance of the best
seed. Final scores use additive fusion without subtracting from a node's
normalized dense component:
\begin{equation}
s(v)=r(v)+\lambda_{\mathrm{g}}s_{\mathrm{path}}(v),
\qquad \lambda_{\mathrm{g}}{=}0.25.
\end{equation}
A node's absolute fused score cannot decrease, although its rank can fall
when other nodes receive larger graph contributions.
Invalidated nodes remain reachable so revision-audit queries can surface
overturned claims. These hyperparameters are frozen defaults and are not
tuned on the real-trace queries.

\paragraph{Learned relation-aware encoding (EPGM R-GCN).}
EPGM R-GCN is trained only on the synthetic execution-provenance
benchmark. Nodes are encoded once with frozen
E5-base-v2~\cite{wang2022text} (\texttt{query:}/\texttt{passage:}
prefixes), concatenated with a 16-d node-type embedding, and projected to
256-d states. Three R-GCN layers~\cite{schlichtkrull2018modeling} use a
28-relation message vocabulary (non-\texttt{feeds} types plus two
\texttt{feeds} binding buckets, each bidirectional):
\begin{equation}
h_v'
=
\operatorname{LayerNorm}\!\Big(
\operatorname{ReLU}\big(
W_0 h_v
+
\operatorname{Dropout}\big(
\sum_{r\in\mathcal{R}}
\sum_{u\in\mathcal{N}_r(v)}
w_{uv} c_{v,r}^{-1} W_r h_u
\big)
\big)
\Big),
\end{equation}
where $\mathcal{N}_r(v)$ is the incoming neighborhood of $v$ under
message relation $r$, and $c_{v,r}=|\mathcal{N}_r(v)|$ normalizes that
relation's incoming messages.
Candidate and dependency MLPs score \texttt{ToolOutput} nodes and induced
logical transitions; training minimizes
$\mathcal{L}=1.0\mathcal{L}_{\mathrm{cand}}+0.5\mathcal{L}_{\mathrm{edge}}$
with mixed easy/hard negatives. Inference decodes thresholded successors
among top-5 sources in a top-16 pool and emits a public logical edge only
when both endpoints remain in the final top $k$. Further optimizer and sampler details are provided in the supplementary
material; tables use the shared protocol in the experimental setup.

\paragraph{Conventional evidence-path encoding.}
On HotpotQA, 2WikiMultiHopQA, and MuSiQue-Ans, relation-aware propagation
runs on dataset evidence graphs with sequential, query-overlap,
entity-overlap, and bridge edges. Dense-FT R-GCN is the full model for
this evidence-graph setting; RQ1 compares complete support and path recovery
across the resulting retrievers.

\subsection{Experimental Setup}

\paragraph{Research questions and evaluation overview.}

relation-aware graph retrieval improves complete evidence-set recovery
on large-scale multi-hop benchmarks under a fixed top-$k$ budget.

controlled execution-provenance trajectories, and which structural

\paragraph{Datasets and splits.}

MuSiQue-Ans v1.0. For each dataset, we retain its training set,
deterministically shuffle the labeled development set with split seed 13,

remaining shuffled examples as a held-out evaluation split. We additionally
construct a controlled execution-provenance benchmark from
2WikiMultiHopQA. It maps each recoverable ordered pair of supporting facts
to typed tool calls, tool outputs, and one output dependency. The converter keeps at most 32 candidate outputs per task and uses a pinned
hybrid successor scorer with equal BM25/dense weight. Each source ranks
non-self candidates from the question plus source evidence. For every
source output, schema v3 creates exactly two ordinary \texttt{feeds}

near (ranks 2--4), mid (5--8), or tail (9+) bucket. The required dependency

label-conditioned benchmark places the required path in the inference graph

\paragraph{Metrics.}
Recall@$k$ measures the fraction of gold evidence retrieved in the
top $k$, while Full Support@$k$ is one only when all gold evidence is
present, so it directly measures whether the complete support set is
recovered. MRR measures the rank of the first gold item. Connected
Evidence Recall is one only when all gold nodes enter the top $k$ and those
gold nodes are connected within the top-$k$ induced graph. Path Recall@10
is a per-query binary measure requiring both (i) all gold dependency
endpoints in the top 10 and (ii) every directed gold dependency reachable
in the returned subgraph. It is averaged over queries with a nonempty gold
dependency set. Edge Recall@10 measures direct recovery of gold
dependency edges. Edge metrics are micro-aggregated against all gold dependencies. Edge
Precision@10 divides true-positive edges by emitted edges whose endpoints
are both in the top 10; Edge Recall@10 divides by all gold edges, so a gold
edge with a missing top-10 endpoint remains a false negative. Edge F1@10
combines these two quantities. Abstention rate is the fraction of considered top-5 source outputs
that produce no accepted dependency after pool, threshold, and conflict
filtering. Average retrieved edges counts public logical output-to-output
edges, not the two native \texttt{feeds}/\texttt{returns} edges used to
reconstruct each trace. HotpotQA does not provide directed gold dependency
paths, so we report connectivity rather than path and edge metrics for that
dataset. A dash in the path columns indicates that a method does not return a
retrieved evidence subgraph with visible candidate-to-candidate edges, so
the metric is undefined rather than zero.
To further distinguish ``retrieving part of the evidence on average''
from ``recovering the complete support chain,'' we also use the
completeness gap
$\Delta_{\mathrm{comp}}@k=\mathrm{Recall}@k-\mathrm{Full\ Support}@k$
as a diagnostic quantity. A smaller gap means that ordinary recall is
less inflated by examples in which only part of the gold evidence is
retrieved. It is used to interpret the primary metrics rather than as
an additional headline metric.

\paragraph{Model and ablation protocol.}
We use the EPGM R-GCN from Section~\ref{sec:evidence-tracing} on the shared
74,012/2,850/2,851 splits (seeds 13, 17, and 29; joint checkpoint rule;
sparse decoder). The detailed rows currently populated below are the
completed seed-13 snapshot; seeds 17 and 29 will be aggregated only after
all full/ablation pairs pass the same artifact-identity checks.
The full model uses 714,245 pairs; w/o hard negatives uses 444,072. We
compare the full model to four training ablations and reserve one paired
inference-time ablation.

\emph{w/o graph} sets the number of graph-convolution layers to zero while
retaining the input projection, node-type embedding, candidate and edge
heads, logical-transition enumeration, and structured decoder.
\emph{w/o edge type} retains topology, relation IDs, and weights but shares
one linear message transform across all relation IDs. \emph{w/o edge
weight} changes only \texttt{feeds} messages: each source's two artifact
weights are replaced by their mean (0.75/0.75 under this construction), so
endpoints, relation IDs, directions, and total source message mass are
preserved; non-\texttt{feeds} weights are unchanged. \emph{w/o hard
negatives} rebuilds 444,072 pairs after setting successor, predecessor,
dense, BM25, and graph-neighbor hard-negative requests to zero, retaining
only positives and two easy random requests per positive while leaving the
full edge loss active. \emph{w/o edge rerank} must reuse the exact full-model
pairs and checkpoint for the same seed, disable only target promotion, and
retain thresholded edge diagnostics. It will enter the final table only when
that checkpoint identity is verified; the earlier unpaired seed-13 artifact
is not used for causal attribution.

Within each seed, every training ablation selects its own development
checkpoint under the joint objective. The current full seed-13 row matches
Table~\ref{tab:provenance}. For the final analysis, each variant's metrics
will be summarized as mean $\pm$ sample standard deviation across the three
seeds. For every ablation and metric, predictions will be paired with the
full model by seed and task ID; full-minus-ablation per-query deltas will be
pooled across matched seed-query pairs and summarized with a 95\% percentile
bootstrap interval (2,000 resamples; bootstrap seed 13). Positive deltas
therefore favor the full model. Full-Support@5/@10 discordant counts
(full-only versus ablation-only successes) will be reported alongside the
intervals in the supplementary material.

In the seed-13 snapshot, removing graph message passing causes the largest
observed quality degradation. Relative to the full model, \emph{w/o graph} drops
Full Support@5, MRR, and Path Recall@10 by 12.00, 12.09, and 10.84 points,
and Edge Precision@10 and Edge F1@10 by 30.86 and 23.32 points. In sample
counts, \emph{w/o graph} completely recovers 342 fewer trajectories at

Recall@2 is nearly tied with the full model, further showing that under
sparse decoding the gain from graph propagation concentrates in complete
support and dependency-edge quality rather than the first hit under a very
small budget. Because this variant retains the same frozen text
representations, node-type embeddings, candidate MLP, and dependency-edge

neighborhood information exchange rather than to the text encoder or output
heads. Three-layer propagation allows upstream evidence and the query anchor
to influence downstream outputs through the call hierarchy and
\texttt{feeds}/\texttt{returns} connections, which is consistent with the
improved joint recovery of both gold outputs under a small budget.

Replacing relation-specific transforms with a shared transform lowers the
quality of predicted dependency edges: Edge Precision@10 and Edge F1@10
fall by 9.84 and 6.26 points, MRR by 3.23 points, and Full Support@5 by
1.62 points (46 fewer complete top-5 trajectories, and incomplete top-10
trajectories rise from 20 to 31). Notably, this variant's Recall@2 is
10.98 points \emph{above} the full model, while its dependency-edge
precision is lower. Untyped propagation therefore favors the very early
candidate ranking on this split but does not preserve the full model's
edge-selection quality. This variant retains exactly the same
adjacency, propagation depth, and edge weights; the only difference is
whether $W_r$ distinguishes relations. The observed single-seed difference
is consistent with a contribution from typed propagation to dependency-edge
quality: the directions and semantics carried by call-hierarchy edges and
field-level data-flow edges are not fully replaced by one untyped
transformation, particularly when
separating structurally adjacent but functionally different \texttt{Agent},
\texttt{ToolCall}, and \texttt{ToolOutput} messages.

The evidence for edge weights also concentrates on precision and the path
side. Replacing each source's two \texttt{feeds} confidences by their mean
lowers Edge Precision@10, Edge F1@10, and Path Recall@10 by 4.36, 3.45,
and 2.35 points and MRR by 0.54 points; at the same time, Full Support@5
dips by only 0.21 points while Full Support@10 rises by 0.21 points (6 fewer
and 6 more complete examples among 2,851 test queries, respectively).
Calibrated within-source weights therefore mainly improve dependency-edge
quality, path recovery, and MRR, while their effect on top-$k$ complete
support is approximately neutral on this split. This
matches the implementation: weights directly scale propagated messages and
can alter fine-grained candidate order and dependency-edge logits, but
Full Support does not change as long as both gold outputs remain inside the
same top-$k$ set. Removing hard negatives leaves metrics essentially flat:
MRR rises by 0.65 points, Edge Precision@10 and Edge F1@10 fall by only
1.31 and 0.78 points, and Full Support@5 is nearly unchanged. Hard
negatives are therefore better characterized as an auxiliary training
strategy in this setting, showing only a weak and directionally
inconsistent independent contribution under a single seed.

\paragraph{Residual errors point to second-hop coverage rather than
indiscriminate subgraph expansion.}
Manual inspection of all 20 residual top-10 failures shows that in 16
cases the model recovers one of the two gold outputs and misses the other;
only four cases miss both. The remaining errors are therefore mostly
``near-complete but missing one hop,'' and future improvements should
prioritize seed coverage and joint ranking for the second dependency
output rather than merely expanding the returned subgraph. Because a
dependency edge is decoded only after both endpoints enter the top-10
set, these 16 single-endpoint misses also explain why small changes in
candidate recall are simultaneously reflected in Path@10 and Edge@10.

Output density further argues against, within these ablations, the
alternative explanation that predicting more edges is sufficient to raise
edge recall. \emph{w/o graph}
returns 1.48 edges on average, the most of any variant, yet is the lowest
on both Edge Recall@10 and Edge Precision@10 (79.94\% and 53.84\%); \emph{w/o
edge weight} and \emph{w/o hard negatives} return 1.10 and 1.09 edges on
average, also more than the full model's 1.07, yet achieve lower Edge
Recall@10. The full model therefore obtains the highest Edge Precision@10 and Edge
F1@10 while emitting the fewest average edges among the training ablations.
This pattern indicates that typed transforms and calibrated weights improve
dependency selection rather than merely making the decoder connect more
candidates.
The decoder keeps at most one
successor per source, which matches the two-hop chain structure of this
synthetic benchmark; natural trajectories in which one output is consumed
by multiple calls will additionally require evaluation of branching
decoders and edge precision.

Taken together, the completed seed-13 run suggests the following provisional
hierarchy. Graph message passing has the largest observed association with
complete support, dependency recall, and edge precision; relation-specific
transforms show a second observed gain in dependency-edge quality; and
source-calibrated edge weights show a smaller, metric-dependent association.
Hard-negative supervision has a weak and directionally mixed seed-13 effect
despite increasing the pair set from 444,072 to 714,245. This hierarchy will
be retained, weakened, or revised according to the three-seed means and
paired intervals in Table~\ref{tab:provenance-three-seed}.

\paragraph{Controlled mechanism example.}
To illustrate how structured provenance converts a partial hit into a
complete hit under the RQ2 protocol, we analyze a reasoning-type
provenance query derived from 2WikiMultiHopQA: ``Who is Anne Woodville's father-in-law?'' (gold
answer: Edmund Grey, 1st Earl of Kent). The query requires a two-hop
dependency: first Anne Woodville's spouse George Grey, 2nd Earl of Kent
is obtained through the \texttt{spouse} relation (first-hop output), and
then that spouse's father Edmund Grey is obtained through the
\texttt{father} relation (second-hop output). In the execution-provenance
graph, each step corresponds to a \texttt{ToolOutput} node, and the
second-hop output depends on the first-hop output through
\texttt{feeds}/\texttt{returns} edges.

Dense retrieval hits the first-hop output within the top-10 but misses the
second-hop output, so it falls into a \texttt{missing\_full\_support}
failure: it finds the spouse information that is semantically related to
the query directly, but cannot locate the indirect ``spouse's father''
dependency by text similarity alone. EPGM R-GCN recovers the complete
dependency pair on the same query: three-layer relational propagation lets
the first-hop output representation flow to the second-hop candidate along
\texttt{feeds}/\texttt{returns} edges, the dependency head assigns this
logical transition a high score, and both gold outputs are brought into the
top-$k$ set while the \texttt{spouse}$\rightarrow$\texttt{father}
dependency path is reconstructed. This is consistent with the aggregate
conclusion from Table~\ref{tab:provenance-budget}: the structural gain
concentrates on completing the second hop of the dependency set rather
than on improving the rank of the first relevant output.


\subsection{Real Multi-Agent Trace Study (RQ3)}

\paragraph{Setting: one naturalistic session, qualitative comparison.}
Automatic ranking metrics are primary for RQ1--RQ2. RQ3 instead inspects
how retrievers behave on SupplyChainTrace, a single web-enabled
supply-chain security session over seven pinned PyPI dependencies
(\texttt{requests==2.19.1}, \texttt{urllib3==1.24.1},
\texttt{PyYAML==3.13}, \texttt{Jinja2==2.10}, \texttt{Django==2.2.0},
\texttt{cryptography==2.3}, \texttt{Werkzeug==0.14.1}).
The session comprises a root coordinator, seven per-package subagents,
an independent verifier, and two verification workers. The recorded
provenance graph contains 150 retrievable nodes (task, agents, tool outputs,
observations, claims, verifications, decisions, and the final answer)
and includes genuine revision structure: early claims (Django
minimum-safe upgrade 4.2.26; a PyYAML-first ranking) are overturned via
\texttt{contradicts}/\texttt{invalidates} after verification, while
invalidated claims remain for audit.

We compare BM25, dense retrieval, FastGraphRAG-style entity search, and
typed-beam EPGM on the same candidate pool, without task-specific
training or trace-specific tuning. Because a single session cannot
support stable leaderboard claims, we do \emph{not} treat aggregate
Recall or Full-Support tables as primary evidence for RQ3. The analysis
below walks representative queries and contrasts what each method
returns.

\paragraph{Revision query: typed edges surface overturned claims for
audit.}
Consider a query that asks what Django's minimum-safe version was first
judged to be, why that judgment changed, and what the final decision is.
The overturned claim \texttt{claim\_537BCA895F} (initially asserting
4.2.26) is ranked eighth by pure dense retrieval. Typed-beam EPGM raises
it to rank five by walking
\texttt{verify\_28A134BF07}$\xrightarrow{\texttt{contradicts}}$
\texttt{claim\_537BCA895F}, returns the contradiction path, and exposes
\texttt{lifecycle\_state=invalidated}. Dense retrieval already places the verification and invalidated claim in
the top 10, but returns them as independent records; typed-beam EPGM makes
the \texttt{contradicts} relation explicit and returns the revision path.
FastGraphRAG-style entity bridges likewise do not encode revision
semantics. The point is mechanistic: provenance structure
answers an audit question in the form the user asked, not that a 20-query
average score is decisive.

\paragraph{Support-chain query: graph traversal recovers evidence buried
by surface form.}
Query Q10 asks why version-range checks must use PEP~440 / SpecifierSet
semantics rather than naive string comparison. Three gold support nodes
are required. Dense retrieval ranks the three support nodes at 3, 10, and outside the
top 10 because two have little surface overlap with the query
(\texttt{claim\_0144C746E7} and \texttt{obs\_42BF2FFDED}).
FastGraphRAG-style returns only one of the three in its top 10.
Typed-beam EPGM anchors on a densely high-ranked PyYAML claim and walks
$\texttt{obs}\xrightarrow{\texttt{supports}}\texttt{claim}$ edges,
placing the three nodes at ranks 7, 9, and 3 and thereby recovering the
complete support triple. The same pattern appears on a related
cryptography upgrade query, where entity-graph search again under-covers
the multi-node support set while typed traversal follows recorded
dependencies. Structure reconnects evidence that text similarity
isolates; this is a case reading, not a multi-session significance test.

\paragraph{What this study does and does not show.}
SupplyChainTrace shows that the full EPGM schema can be populated from a
real multi-agent run with tool calls, parallel handoffs, and evidence
revision. In the two inspected cases, typed-beam retrieval uses support
and contradiction edges to return an explicit path or complete a support
set that the compared rankings leave implicit or incomplete. It does not provide a scored
real-world benchmark, does not evaluate EPGM R-GCN transfer, and does
not replace RQ1--RQ2 automatic results. Expanding to more sessions and
end-to-end tasks remains future work.

\subsection{Cross-Setting Analysis}

Across the three protocols, relational structure helps most when
relevance is split across dependent artifacts rather than concentrated in
a single surface-similar record. RQ1 yields higher complete-support point
estimates for relation-aware encoding on large multi-hop sets; RQ2 shows
the largest single-seed ablation drop when message passing is removed; and
RQ3's cases show the same schema supporting audit and support-path retrieval
on a real session where flat rankings leave relations implicit or evidence
outside the cutoff. The settings
are not interchangeable: multi-hop QA lacks native tool executions,
synthetic trajectories lack natural noise and true revision events, and
the real trace is too small for training or multi-seed claims. Read
together, they support applicability of the structured-retrieval
hypothesis under complementary constraints, not a universal real-world
SOTA result.

\subsection{Efficiency and Cost Analysis}

\paragraph{Structured retrieval increases observed latency while improving
complete-support recovery.}
The ms/query column of Table~\ref{tab:provenance} characterizes the
retrieval cost of each method. The reported training-free dependency-path preset averages 39.04 ms per
query, compared with 37.51 ms for Dense and 105.53 ms for the evaluated
FastGraphRAG-style implementation in this harness. Thus, bounded
execution-path search adds little observed latency beyond its dense base in
this run. Learned relation-aware propagation raises the EPGM R-GCN mean
latency to 68.69 ms per query on the delivered full run (median
67.61 ms over the 2,851 test queries), trading additional computation for
large gains in complete support and dependency recovery over Dense-FT. BM25
remains fastest at 0.60 ms per query, but its complete-support recovery is
far below all dense and graph methods. Baseline latencies were measured in
the same evaluation harness on the shared 2,851-query test split; the EPGM
R-GCN latency is the mean per-query time from the delivered full artifact.
These values are observed retrieval times rather than a controlled systems
benchmark with fixed hardware and caching, and they exclude data
generation, graph construction, and model training.

\subsection{Limitations and Robustness}

The experiments already provide partial evidence for structured
execution-provenance memory from three perspectives: controlled retrieval,
complete evidence recovery, and dependency reconstruction. Their scope is
still concentrated on offline retrieval over fully materialized static
graphs, so they provide only partial support for the full multi-agent
memory lifecycle. In particular, we do not measure streaming online graph
updates, mid-trajectory retrieval, or incremental index maintenance;
\textsc{UpdateGraph} is a schema-level description of event-local
construction, not an evaluated systems component. First, the synthetic
provenance benchmark is deterministically derived from labeled
question-answering evidence chains rather than collected from
heterogeneous, naturally occurring agent logs. The conversion also uses
supporting-fact information to materialize the required dependency as an
ordinary semantic head or rank-matched branch and rejects examples for
which a matched non-gold branch cannot be formed. The near-ceiling EPGM R-GCN numbers show recovery on a controlled,
label-derived topology where required \texttt{feeds} edges are inserted as
ordinary heads or rank-matched branches. This does \emph{not} by itself rule
out converter-specific shortcuts; controls such as shuffling \texttt{feeds}
endpoints at matched degree, topology-only baselines, or relation holdouts
are not yet reported. SupplyChainTrace is analyzed qualitatively for schema applicability and
case-level retrieval behavior, not as a scored multi-session benchmark.

Second, at this draft stage the populated ablation tables---and the main
EPGM R-GCN and Dense-FT comparison---are seed-13 snapshots. Seeds 17 and 29,
per-variant mean/standard-deviation summaries, and paired confidence
intervals are not yet complete. Table~\ref{tab:provenance-three-seed}
therefore remains explicitly pending. The few-tenths-of-a-point reversals
after source-mean edge weighting or hard-negative removal must not be given
a stable direction until that table is populated. Removing graph
propagation currently shows the largest cross-metric seed-13 drop, but its
final magnitude and uncertainty will be reported from the same three-seed
protocol rather than inferred from the current point estimate alone. Third, the current experiments
evaluate retrieval, complete support, and path recovery, so they can
partially support the claim that structured memory provides more complete
grounding for downstream reasoning; system-level effects such as ``reducing
unsupported claims'' or ``improving downstream impact-tracing accuracy''
receive only indirect support until the retrieved subgraphs are connected
to real decision or generation tasks. The reported tables already include edge
precision and F1, showing that the structural components' gains lie in
dependency-edge quality rather than recall alone; adding branch-level
completeness would more fully quantify overprediction and multi-branch
recovery.

Fourth, \emph{w/o graph} removes only graph message passing while
retaining node-type embeddings, the candidate scorer, logical transitions
enumerated from graph structure, and the dependency-edge head, so it
answers whether propagation is necessary rather than capturing every
difference between a graph model and a fully flat model. The independently
trained Dense-FT in the main experiment already provides the flat text
baseline; to further localize each piece of structural information, future
work should separately remove node types, field-binding features, and the
edge-prediction loss, shuffle the data-flow relations, and evaluate
invalidation penalties on trajectories containing actual evidence-revision
events. Overall, the current results provide quantitative evidence for
compact support recovery and dependency decoding on the evaluated evidence
graphs and controlled provenance benchmark, plus qualitative applicability
evidence on
one naturalistic trace. They provide only partial support for a complete
multi-agent memory system; broader system-level conclusions require
multi-seed repetition, more natural trajectories, and end-to-end tasks.


\section{Conclusion}

We proposed Execution-Provenance Graph Memory for evidence-path and
execution-dependency retrieval in evidence-heavy agent systems. EPGM
represents tasks, agents, tool calls, tool outputs, and related artifacts
as a typed provenance graph whose native edges expose call hierarchy and
field-bound data flow. A training-free structured retriever and a learned
EPGM R-GCN recover compact support sets and logical dependencies instead of isolated
records. Across large-scale evidence benchmarks, controlled
execution-provenance trajectories, and a real multi-agent trace study, the
results support the same underlying conclusion: relational structure is
most useful when relevance is distributed across dependent artifacts.
The reported seed-13 large-scale runs show 4.33--13.01-point Full
Support@5 gains over task-adapted dense retrieval; the current seed-13
controlled snapshot shows a 13.72-point gain, while the reserved three-seed
analysis will quantify its variance and paired uncertainty. Removing graph
propagation currently produces the largest observed seed-13 ablation drop;
and real-trace cases show typed traversal exposing support and revision
paths that flat rankings separate. These findings motivate treating
multi-agent memory as execution provenance rather than semantic recall
alone. They do not
yet prove gains on arbitrary real-world multi-agent deployments;
the pending three-seed stability analysis, broader natural logs, and
end-to-end revision or generation metrics remain necessary before final
claims.
