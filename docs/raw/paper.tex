\title{When Does Execution Provenance Help Agent Memory Retrieval?}
\author{Anonymous Author(s)}

\begin{document}

\begin{abstract}
Long agent executions contain useful memory in tool arguments and outputs, but relevant evidence may be distributed across several events and must fit within a limited downstream context. We study this problem on real operating-system agent traces by constructing natural memory queries with exact source-span supervision over ISETrace. The resulting evaluation uses 2,000 held-out natural queries from 1,207 trajectories and distinguishes direct, linked, and multi-fact recall. We compare flat lexical and dense retrieval, an entity-based graph baseline, a training-free provenance completion method, fine-tuned dense retrieval, and a relation-aware graph convolutional retriever over a query-independent execution-provenance graph. Preliminary seed-13 results show that the natural-only provenance R-GCN improves Coverage@1024, Coverage@2048, and Full Support@2048 over natural-only Dense-FT by 8.82, 7.57, and 10.40 percentage points, respectively, while reducing Recall@5 and MRR. Under mixed natural and template supervision, the graph advantage is concentrated in linked and multi-fact queries and is absent for direct recall. Template-only training transfers poorly to natural queries. These findings suggest that execution provenance is most useful for completing distributed evidence under a token budget, rather than universally improving early ranking. Multi-seed estimates and human validation of the authored queries are pending; the corresponding result slots are reserved in this draft.
\end{abstract}

\keywords{agent memory, information retrieval, execution provenance, graph neural networks}

\section{Introduction}
\label{sec:introduction}

Language agents retain increasingly long histories of messages, tool calls, and tool outputs. Memory systems retrieve selected parts of those histories when the full execution no longer fits in the context window~\cite{park2023generative,packer2023memgpt,shinn2023reflexion}. Most implementations represent memory as chronological text, summaries, or independently embedded chunks. Such representations support semantic recall, but a query may require several related events rather than one individually relevant chunk.

This creates an \emph{evidence-completion} problem. Suppose an agent remembers a file name produced by one tool, a later command that consumed it, and the final output containing the requested value. A dense retriever may rank one of these fragments highly while omitting another fragment that is only indirectly related to the query. The failure is especially important under a fixed context budget: retrieving one good fragment is not sufficient when all supporting spans are required.

Execution traces contain structure that may help. A tool call returns an output; a call owns argument content; an output owns content chunks; artifacts are read and written; and values from an earlier output may reappear in later arguments. These observable relations form \emph{execution provenance}. Unlike a semantic entity graph, provenance records how content is produced and consumed. Unlike a manually designed causal graph, however, it does not by itself establish that one event logically caused, supported, verified, or invalidated another.

Evaluating this hypothesis on real traces is difficult because released trajectories rarely include memory queries or source-grounded evidence labels. We therefore construct an exact-span retrieval protocol over ISETrace, a collection of recorded operating-system agent sessions. The official release supplies messages and executed tool interactions but not memory-search supervision. We author natural queries from trajectory-local source packets, reserve a trajectory-disjoint held-out test set after validation, and require every gold item to be an exact quote that maps back to a unique source span. This design evaluates retrieval against the original trace rather than against generated answers or synthetic node identifiers.

We compare two retrieval views. Flat methods rank overlapping 512-token chunks rendered from the complete trajectory. Provenance methods rank source-backed tool-argument and tool-output content units connected by a query-independent graph. Because these views use different candidate segmentation, our principal comparison is under a fixed retrieved-token budget, with exact source spans serving as the common evaluation coordinate. We also report fixed-$k$ metrics as diagnostics and explicitly separate the effect of provenance-aware representation from graph propagation in the planned ablations.

Our study asks three questions:
\begin{itemize}
    \item \textbf{RQ1:} Does execution-provenance retrieval improve exact-span evidence coverage under a fixed token budget relative to flat and entity-graph retrieval?
    \item \textbf{RQ2:} For which memory-query types---direct, linked, or multi-fact recall---does provenance provide the largest benefit, and how does this differ from early ranking quality?
    \item \textbf{RQ3:} Does deterministic provenance-template supervision transfer to held-out natural memory queries?
\end{itemize}

The preliminary evidence supports a conditional rather than universal advantage. Both training-free provenance completion and the learned R-GCN improve token-budget coverage. The learned advantage is largest for linked and multi-fact queries, while flat Dense-FT remains competitive for direct recall and stronger on several top-$k$ metrics. Moreover, template-only supervision generalizes poorly, and adding templates does not uniformly improve the graph model.

Our contributions are:
\begin{itemize}
    \item We formulate source-grounded memory retrieval over real agent executions and construct a trajectory-disjoint ISETrace evaluation protocol with natural queries, exact source spans, and direct/linked/multi-fact strata.
    \item We instantiate a conservative, query-independent provenance graph using only observable tool-call, tool-output, content, value-flow, and resource relations, and evaluate both training-free completion and learned relational propagation.
    \item We show that the value of provenance depends on the evaluation budget and query structure: it improves distributed evidence completion more consistently than first-hit ranking, while deterministic structural templates exhibit a substantial natural-language transfer gap.
\end{itemize}

\section{Related Work}

\subsection{Memory and Retrieval for Language Agents}
Agent memory stores observations, interactions, reflections, and prior task experience outside the immediate context window. Generative Agents use a memory stream with retrieval and reflection~\cite{park2023generative}; Reflexion stores verbal feedback across trials~\cite{shinn2023reflexion}; and MemGPT treats memory movement as an operating-system-style resource-management problem~\cite{packer2023memgpt}. These systems establish the importance of persistence but largely retrieve flat records. Our focus is narrower: recovering all source-grounded evidence needed by a memory query from one long execution.

\subsection{Tool-Using Agents and Execution Traces}
Tool-using agents interleave reasoning, action, and observation~\cite{yao2023react,schick2023toolformer,karpas2022mrkl}. Their logs naturally expose tool calls and outputs, which can be retained as memory. Multi-agent frameworks add communication and coordination~\cite{wu2023autogen,li2023camel}, but the present dataset contains user--agent/tool sessions rather than explicit multi-agent collaboration. We therefore make claims about agent execution traces, not multi-agent coordination or downstream agent correctness.

\subsection{Dense and Graph-Based Retrieval}
Retrieval-augmented generation and dense passage retrieval rank textual units by lexical or embedding relevance~\cite{lewis2020rag,karpukhin2020dpr}. GraphRAG-style systems connect entities or passages and expand retrieval through semantic structure~\cite{edge2024graphrag,gutierrez2024hipporag,guo2024lightrag}. Such graphs may recover related context, but their edges do not necessarily encode the call--return and producer--consumer structure of an execution. We compare flat, entity-graph, and provenance-graph retrieval within one exact-span protocol.

\subsection{Provenance and Relational Graph Learning}
Data provenance describes the entities, activities, and derivations involved in producing information~\cite{w3c2013provdm,lebo2013provo,missier2013prov}. We adopt this conservative interpretation: graph edges are compiled from observable events and exact bindings rather than inferred semantic causality. For learned retrieval, relational graph convolution applies relation-specific transformations during message passing~\cite{schlichtkrull2018modeling}. Our model uses this mechanism to contextualize source-backed argument and output units before query-conditioned scoring.

\section{Task Definition}
\label{sec:task}

Let a trajectory be an ordered sequence of messages, tool calls, and tool outputs,
\begin{equation}
\tau = (e_1, e_2, \ldots, e_n).
\end{equation}
Every textual event field is addressable by an event identifier, a JSON pointer, and a character interval. A source span is
\begin{equation}
s=(\mathrm{event}(s),\mathrm{ptr}(s),a_s,b_s).
\end{equation}
For memory query $q$, the gold evidence is a set of exact source spans $G_q=\{s_1,\ldots,s_m\}$. A retriever ranks candidate units $c_1,c_2,\ldots$; each candidate has text, token cost $t(c_i)$, and one or more source spans $S(c_i)$.

The target is not answer generation or edge prediction. It is to retrieve source-backed content that covers $G_q$. Consequently, two systems may expose different candidate units as long as both map their output to the original trace. This common coordinate is essential because flat chunks and provenance units have different boundaries.

\subsection{Memory-Query Types}

We use three authoring categories:
\begin{itemize}
    \item \textbf{Direct recall:} the query requests a fact stated in one localized execution event.
    \item \textbf{Linked recall:} the remembered clue and requested fact occur in related events, requiring a producer--consumer or call--output link.
    \item \textbf{Multi-fact recall:} the query requires multiple facts distributed across events.
\end{itemize}
These categories are content-addressed metadata used for stratified evaluation, not inputs to the retrievers. The preparation pipeline preserves the query-ID-to-category mapping in its dataset artifact and copies it into per-query metric rows.

\section{ISETrace Memory-Query Construction}
\label{sec:data}

\subsection{Source Trajectories and Deterministic Trajectory Splits}

ISETrace provides 23,132 recorded operating-system agent trajectories.\footnote{\url{https://huggingface.co/datasets/valiere/ISETrace}} Each released record is a user--agent/tool session containing messages, tool definitions, executed calls, and tool outputs. The release does not natively include memory-search queries or gold evidence spans; those are constructed in our pipeline.

We pin source revision \texttt{e40e04d}. Before query authoring, the complete raw trajectory collection is deterministically shuffled with authoring seed 13. After authored records are validated and resolved back to their source trajectories, the first 1,207 distinct trajectories in authored-query order form the natural test set. Natural train and development trajectories are selected from the remaining authored-query trajectory pool with split seed 13. Every query belonging to one trajectory remains in the same split, and trajectory identifiers are disjoint across train, development, and test. This protocol controls exact trajectory overlap but does not use intent-component grouping or claim zero overlap in normalized intent text or source intent identifiers. Authoring and split seeds remain fixed in the planned multi-seed experiments; only model-training seeds vary.

\subsection{Natural Query Authoring}

Natural queries are authored from trajectory-local source packets with \texttt{gpt-5.6-luna}, prompt version 7, and authoring seed 13. The author must return one or more exact quotes from tool arguments or tool outputs. Each quote is accepted only when it can be uniquely localized to its source event and converted to an exact character span. Split ownership is then assigned deterministically at the trajectory level, so all accepted queries resolved to the same trajectory remain together.

The frozen preliminary test artifact contains 2,000 natural queries from 1,207 test trajectories. Of these, 641 are direct, 906 linked, and 453 multi-fact queries. There are 1,363 one-span queries and 637 queries with at least two gold spans. \subsection{Deterministic Template Supervision}

For auxiliary training, deterministic templates are compiled from provenance motifs rather than generated as paraphrases of natural queries. The motif families are value flow, artifact lifecycle, multi-hop flow, and multi-source join. Template labels identify the output-content units associated with the motif focus. The mixed setting uses a 1:3 ratio of natural to template tasks in train and development, while testing remains exclusively natural. A template-only R-GCN stress-tests transfer without any natural-query supervision.

\subsection{Query-Quality Status}

The exact-span checks establish quote locality but do not establish that every query is natural, unambiguous, or fully supported by its selected quotes. At the time of this draft, the authored queries are engineering data and have not completed human review. We therefore report the present results as preliminary. Before submission, the test set will be manually audited for query clarity, evidence sufficiency, span minimality, and alternative valid evidence; the reviewed artifact and its hash will be frozen.

Tool-call and tool-output nodes preserve event identity and call--return structure. Their content is divided into source-backed chunks. Resource edges are compiled from observable artifact references. The \texttt{feeds} relation is added only when a typed token extracted from an earlier output exactly appears in a later call argument. It is therefore a deterministic lexical binding, not a learned or human-annotated causal dependency. The graph contains no claim, decision, verification, support, contradiction, or revision nodes.

The persisted graph includes \texttt{precedes} edges for trace fidelity. The current provenance path method and R-GCN exclude \texttt{precedes} from traversal/message passing so that generic temporal density does not dominate the more specific physical relations.

\section{Retrieval Methods}
\label{sec:methods}

\subsection{Candidate Views}

\paragraph{Flat trajectory view.}
Messages, reasoning text when available, tool arguments, and tool outputs are rendered into one trajectory document and divided into overlapping 512-token chunks with 64-token overlap. BM25, Dense, GraphRAG, and Dense-FT rank this shared candidate set.

\paragraph{Provenance-unit view.}
Argument and output fields are divided into source-backed content units attached to the provenance graph. Provenance Path and the R-GCN rank these units. This view excludes free-form messages because the present memory-query gold is authored only from tool arguments and outputs.

The candidate views are intentionally part of their respective systems, but this means that flat-vs-provenance comparisons do not isolate graph propagation. The common exact-span metric makes their outputs comparable at the task level; candidate-matched ablations are required for causal attribution.

\subsection{Training-Free Baselines}

\paragraph{BM25 and Dense.}
BM25 ranks flat chunks lexically. Dense retrieval encodes queries and chunks with frozen \texttt{intfloat/e5-base-v2} embeddings and cosine similarity.

\paragraph{GraphRAG.}
The entity-graph baseline builds a private graph over flat chunks using noun-phrase/entity co-occurrence and propagates initial retrieval scores. It tests whether generic semantic graph expansion provides the same benefit as execution provenance.

\paragraph{Provenance Path.}
This method first ranks provenance units with the same frozen dense encoder. It takes the top five candidates as anchors and performs deterministic bidirectional breadth-first traversal over non-temporal provenance edges, with at most six hops, three partners per anchor, and 256 total expansions. The top two dense results are protected. Accepted partners are stably inserted after their anchor; if no proposal is accepted, the method returns the exact provenance-unit dense ranking. Despite the implementation name, this method does not predict or evaluate a gold dependency path.

\subsection{Trainable Baselines}

\paragraph{Dense-FT.}
Dense-FT fine-tunes E5-base-v2 over flat chunks for one epoch, with learning rate $2\times10^{-5}$ and batch size 16. Positives are candidates whose source spans overlap gold spans. Training pairs include two random and two BM25 negatives per positive, with one selected hard negative used by the trainer. The best checkpoint is selected by development cosine-similarity MAP.

\paragraph{Provenance R-GCN.}
The graph model freezes 768-dimensional E5 embeddings for graph nodes and the query. Embeddings are projected to a 256-dimensional hidden space and contextualized with three relational graph-convolution layers. Seven physical relations are represented in forward and reverse directions, giving 14 relation-specific message transformations. Edge weights are uniform. The model has no node-type features, metadata features, dependency-edge decoder, or path loss.

The query is encoded as a disconnected temporary node; graph propagation is therefore query-independent. A query-conditioned MLP scores each argument/output candidate from $[h_v,h_q,h_v\odot h_q]$. Training uses binary node labels, AdamW with learning rate $10^{-4}$, graph batch size 128, dropout 0.1, and 15 epochs. Each positive is paired with two random, two BM25, one dense, and one graph-neighbor negative. The checkpoint is selected by development natural-query Recall@5.

\section{Evaluation}
\label{sec:evaluation}

\subsection{Exact-Span Metrics}

Let $U(G_q)$ denote the set of source-addressed characters in all gold spans, and let $U(C)$ denote the corresponding characters covered by retrieved candidates $C$. Character identities include event and field addresses, preventing text copied from another event from receiving credit. Coverage is
\begin{equation}
\mathrm{Cov}(C,q)=\frac{|U(G_q)\cap U(C)|}{|U(G_q)|}.
\end{equation}

For token budget $B$, evaluation consumes the ranked prefix in order and stops before the first candidate that would make cumulative token cost exceed $B$. Calling this prefix $C_B$, the primary metric is $\mathrm{Coverage}@B=\mathrm{Cov}(C_B,q)$. Full Support is
\begin{equation}
\mathrm{FS}@B(q)=\mathbb{1}[U(G_q)\subseteq U(C_B)].
\end{equation}
We report budgets 512, 1024, and 2048.

Evidence density divides covered gold characters by the total source-span characters of retrieved candidates. Span F1 is the harmonic mean of coverage and density. Because density is character-based while the selection budget is token-based, Span F1 is a diagnostic rather than the sole headline metric.

\paragraph{Fixed-$k$ diagnostics.}
The reported Recall@$k$ is also character-span coverage, evaluated on the first $k$ candidates; it is not evidence-item recall. MRR uses the rank of the first candidate overlapping any gold span. The current ISETrace protocol has no independently annotated path or edge gold, so Path Recall and Edge Recall/Precision/F1 are undefined and are not reported.

\subsection{Comparison Protocol}

Every method uses the same 2,000-query natural test artifact and top-$k=10$ output depth. The split and authored queries remain fixed across training seeds. Flat methods expose an average of 131.66 candidates per test trajectory, while provenance methods expose 124.54. We therefore prioritize token-budget metrics over fixed-$k$ comparisons. Trainable methods are compared under matched supervision composition: natural-only Dense-FT against natural-only R-GCN, and mixed Dense-FT against mixed R-GCN.

\section{Results}
\label{sec:results}

\subsection{RQ1: Provenance Improves Token-Budget Coverage}

Table~\ref{tab:seed13} reports the completed seed-13 runs. Among training-free methods, Provenance Path improves Coverage@512/1024/2048 over frozen Dense by 11.05, 14.07, and 12.38 percentage points and improves Full Support@2048 by 14.75 points. GraphRAG approximately matches BM25 and does not reproduce the provenance improvement.

\subsection{RQ3: Template Supervision Has a Natural-Query Transfer Gap}

Adding three template tasks per natural task improves Dense-FT Coverage@1024 from 42.17 to 46.63, but lowers R-GCN Coverage@1024 from 51.00 to 49.39 and Full Support@2048 from 63.35 to 60.70. At the same time, mixed R-GCN improves several fixed-$k$ metrics over natural-only R-GCN. Thus, templates alter the ranking--coverage trade-off rather than providing a uniform benefit.

The stronger negative result is template-only transfer. Despite using substantially more deterministic training tasks, template-only R-GCN reaches only 23.89 Coverage@1024 and 26.80 Full Support@2048 on natural queries. Structural templates are therefore not substitutes for natural-query supervision in their current form. Future work should distinguish whether the gap arises from template language, motif distribution, positive-unit selection, or optimization imbalance.

\section{Required Controls and Further Analysis}
\label{sec:controls}

The current flat-vs-provenance comparison combines candidate segmentation with graph structure. To identify the source of the gain, the final study will include three candidate-matched controls. First, a \emph{provenance-unit Dense} baseline will rank the exact candidate units consumed by Provenance Path without graph completion. Second, R-GCN \emph{w/o graph} will replace relational propagation with the identity encoder while retaining the provenance units, frozen embeddings, projection, scorer, pairs, and optimization. Third, relation ablations will remove \texttt{feeds}, resource, and hierarchy/chunk edges, with a degree-matched shuffled-edge control where feasible.

The final artifact report will additionally include graph size and relation distributions, the proportion of trajectories containing each relation, the proportion of gold sets whose provenance units lie in one connected component, the number of candidates selected at each token budget, and results at 256 and 4096 tokens. These diagnostics are necessary to distinguish graph propagation from candidate filtering and to explain which physical relations support linked and multi-fact retrieval.

\section{Limitations}
\label{sec:limitations}

\paragraph{Authored-query validity.}
Exact quoting guarantees source alignment but not question quality. The current test queries were generated by an LLM from selected source packets and remain unreviewed. They may contain lexical cues, omit plausible alternative spans, or reflect the authoring prompt's notion of memory. Formal benchmark claims require a documented human audit and a frozen reviewed release.

\paragraph{Representation confound.}
Flat methods index complete rendered trajectories, whereas provenance methods index only argument and output units. Since gold spans are also selected from arguments and outputs, provenance segmentation supplies a useful inductive bias independently of graph propagation. Until the candidate-matched controls are completed, the main results establish the performance of a provenance-aware retrieval system, not the isolated causal effect of R-GCN message passing.

\paragraph{Observable binding is not causal dependency.}
The graph is compiled from call--return structure, exact typed-token reuse, chunk adjacency, and resource references. A \texttt{feeds} edge does not prove semantic causality or logical support. With no independently annotated path or edge gold, we do not claim dependency recovery, decision tracing, verification tracing, or revision-impact accuracy.

\paragraph{Scope of trajectories.}
ISETrace contains real executed operating-system agent sessions, but it is not an explicit multi-agent collaboration corpus. We do not evaluate agent-to-agent coordination, online memory updates, streaming retrieval, or cross-session memory. The experiments are offline retrieval over complete trajectories.

\paragraph{Training and statistical uncertainty.}
The completed results currently use one model-training seed. Queries from the same trajectory are also not statistically independent. The final report will add multiple training seeds and trajectory-cluster paired intervals. Split and authoring seeds remain fixed because they define the benchmark rather than model variation.

\paragraph{No downstream generation evaluation.}
Exact-span retrieval measures whether evidence reaches the context budget, not whether a downstream model answers correctly or faithfully. We therefore make no claim about answer accuracy, unsupported-claim reduction, or end-to-end agent performance. Such evaluation is complementary future work.

\paragraph{Efficiency reporting.}
The current aggregate and per-task artifacts encode retrieval latency at different apparent scales. We defer latency comparisons until units, hardware, batching, warm-up, and caching are normalized. Graph construction and embedding/index construction must be reported separately from online query latency.

\section{Conclusion}

We introduced an exact-span protocol for studying memory retrieval over real agent execution traces and evaluated flat, entity-graph, and execution-provenance methods under fixed token budgets. Preliminary seed-13 results show a consistent distinction between evidence completion and early ranking. Provenance-aware retrieval, especially the learned R-GCN, places more of the complete gold support into 1024--2048 tokens, while fine-tuned dense retrieval remains stronger on several fixed-$k$ and first-hit metrics. The advantage is concentrated in linked and multi-fact queries and is absent or weak for direct recall. Deterministic template supervision does not uniformly improve natural retrieval, and template-only transfer is poor. These findings motivate a conditional view of graph memory: observable execution structure is useful when evidence is distributed across related events, not as a universal replacement for semantic retrieval. Final claims await human validation, candidate-matched graph ablations, and the reserved multi-seed experiments.

\section{Ethical Considerations}
This study uses recorded operating-system agent traces, which may contain user-authored text, file paths, commands, tool outputs, or other sensitive information. Any release of derived queries, evidence spans, or processed traces should follow the source dataset's license and access terms and should be screened for personal information, credentials, and security-sensitive content. A retrieval system that exposes exact historical content can amplify privacy leakage; practical deployments should therefore enforce access control, data minimization, redaction, and provenance-aware filtering. Our evaluation measures evidence retrieval rather than downstream answer quality, factuality, or safety, and its results should not be interpreted as establishing those properties.
